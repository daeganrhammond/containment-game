# Containment

An early desktop-first prototype for the swipe-to-draw arena game in the parent project brief. Built with Expo and React Native, with browser preview support.

## Run it

```sh
npm install
npm run web
```

## Distribution

Build a static release with `npm run export:web`. The ready-to-host files are written to `dist/`. See [`DEPLOYING.md`](DEPLOYING.md) for hosting instructions and the automatic GitHub Pages workflow. Once the project is connected to GitHub and Pages is enabled, pushes to `main` publish updates to the same game URL.

Use touch or a mouse drag in the arena. On web, the **DRAW WITH: TOUCH / MOUSE** selector uses the swapped mapping requested for browser testing: selecting **TOUCH** enables cursor drag, and selecting **MOUSE** turns cursor drag off. Touch swipes remain active in both modes. A vertical drag grows a vertical wall; a horizontal drag grows a horizontal wall. Release the gesture to start it. Several walls can grow at once, up to the configurable prototype limit. Wall growth speed is controlled in `mechanics.ts`.

## Current prototype rules

- Balls bounce around the arena and off other balls and completed walls. A Speed pickup that hits a metal ball is destroyed and drives that ball to the configured maximum speed without changing its heading. Balls that slow below the recovery threshold receive a speed burst with a small random heading adjustment; by default, each recovery also has a 20% chance to grant an enabled, eligible Splitter, Drifter, or Anchor modifier. Recovery threshold, speed and modifier chance are Developer-tunable.
- An active wall grows from the gesture point toward both anchors. A ball touching it before it connects breaks that wall and costs a life.
- When unfinished perpendicular walls meet, their endpoints stop and connect. The connected network stays breakable until all outer endpoints stop and at least two endpoints are grounded, then the network locks into solid walls.
- When a line/network solidifies, each newly separated region is checked on both sides: any region containing no metal balls is immediately claimed, and any region still containing a ball stays open. Claimed territory is shown in dark fill and is solid to balls and pickups; drawing can start only in open territory.
- Claiming 65% of the original arena advances the stage and adds a ball.
- **Hard Mode** is an optional, off-by-default Developer setting for new runs. After every successful territory capture, the game adds one temporary ball to the largest connected uncaptured region, using normal ball speed and a random direction. These capture-spawned balls last for that level only and do not change the normal number of balls added at future level starts. The setting is saved with balance profiles and the active run.
- Life, speed, battering-ram, and treasure-chest pickups spawn independently at random intervals with configurable weighted rarity. Treasure is eligible on every level, with its 1% spawn weight unchanged. There is no cap on simultaneous pickups. A pickup is captured when its region becomes claimed, when it is isolated from every ball by a completed wall, when a newly solidified wall skewers it, or if it enters already-claimed territory. Captures animate.
- All pickups use a shared radius multiplier of 1.4× the metal-ball radius for rendering and collisions. Pickup artwork may extend past its circular collision shape. Classic Heart has a crimson gloss and distinct double-beat idle/capture pulse. Vital Seed has leaf and vein details, its green aura and orbiting gold motes, and a separate expanding bloom capture effect. Speed pickups have an electric idle effect, ram pickups emit sparks, and treasure chests shine. These animations do not change travel velocity. Metal balls use the selected polished-chrome look, with compact specular highlights and spherical shading. Speed and ram controls sit side by side below the play board; the claim and ball-count tracker is also below the board. The life icons have no count cap and wrap to further rows.
- Capturing a treasure chest queues a conditional treasure-hunt event for the next level. A hidden, stationary jackpot is placed on that level and expires after three minutes. Claiming its territory reveals the chest over the captured background without collecting it. Arm Ram and tap the chest to open it: a successful open costs 3 Ram charges, plays the selected Ram skin's blast effect plus a separate gold-coin/gem burst, then grants 3–6 random pickups (including a possible treasure chest) with their capture effects across the arena. If you miss, the usual one-charge Ram miss and radial blast apply. The three-minute timer continues after reveal and despawns an unopened jackpot at zero.
- Each new level has a 50% chance to start a **Picture** event, alongside any Treasure Hunt. When selected, it makes a second 50/50 roll between a new procedural scene and a random item from the Developer Picture Library. If the library is empty when it rolls that way, it falls back to a fresh procedural scene. Saving the current procedural scene adds its seed to the library used for future levels; imported PNG, JPEG, and WebP images are also available for random selection. Imported files are copied to the app picture folder on native devices; the browser keeps a compact local copy with an approximately 1.5 MB library limit. Procedural scenes use seeded palettes and randomized abstract ridges, branching fractal forms, rings, and flowing ribbons. The art sits under the board: open territory keeps its normal arena color, while claimed territory reveals the matching part of the full-stage picture.
- **Waldo** is a rare pickup: each pickup spawn roll has a 5% chance to select it, and each level independently has a 50% chance to block Waldo spawns for that whole level. It despawns after 30 seconds by default. Capturing it quietly queues the next Picture event to become a Waldo crowd puzzle; it does not add a HUD counter or immediately grant the pet. The Waldo art is revealed through claimed territory. Arm Ram and tap Waldo to spend one Ram, earn the configured Credits (25 by default), play a fireworks celebration, spawn a Treasure pickup, and add Waldo as a pet. A Waldo event chooses a saved Waldo puzzle half the time when the library has entries, otherwise it creates a new puzzle. The Developer tab can save the current puzzle recipe to a Waldo-only library, remove saved puzzles, adjust spawn eligibility/chance, reward and despawn behavior, and test-spawn the pickup. Waldo wanders along the life HUD tending the hearts while not deployed. Drag Waldo into unclaimed territory to deploy; its occupied enclosure stays unclaimed. After 45 seconds of active deployed play, Waldo hangs a painting upon reaching a nearby wall and awards configured Credits (5 by default). Painting value and cadence have Developer settings; Merchant power bars can increase the value per painting for that run.
- Life pickups add one unlimited life. Speed pickups grant a charge: tap Speed to accelerate the newest growing wall by 40%, or preload the next wall if none is growing. A preloaded charge expires after six seconds and shows a countdown.
- Ram pickups grant a charge. Tap Ram, then tap a ball to empower it to break the next player wall it hits without costing a life. A miss spends the charge, does not cost a life, and triggers a centered radial impulse/explosion that can sharply redirect nearby balls and pickups; blast radius and strength are independently tunable. The struck wall alone is removed.
- Lives are unlimited; the HUD shows individual icons that wrap across rows, and each life icon uses the selected heart skin. Speed and Ram controls show their selected pickup skins as ability icons and repeat those icons for the number of charges that fit in each button; when the remaining charges exceed that space, the tracker switches to a numeric total.
- The exact claimed-area percentage appears at the bottom of the arena, rounded to two decimal places.
- The current run and local best-run list persist on the device/browser using AsyncStorage.
- The arena fills the available stage on wide browser and portrait touch layouts. Its logical playfield and capture grid adapt to the displayed aspect ratio at one uniform scale, preserving round projectile art and matching collision sizes. Ball-to-ball and ball-to-pickup collisions use the sum of their radii; wall collision distance uses each projectile radius plus half the wall thickness. Decorative projectile shadows were removed so they do not suggest oversized collision circles.
- The **Developer** tab has a persistent **Skin Catalog** with dropdowns for the arena background, metal balls, each pickup kind, and the wall-break effect (Glass Shards, Ember Snap, or Sonic Shear). Each dropdown shows a visual sample; tap a pickup sample to replay its capture effect. Choices apply immediately and save locally, independently of balance-tuning profiles. Each pickup skin includes its own capture-animation definition, color treatment, and particle motif. Catalog options include all three metal-ball concepts, six heart skins (including the Crimson Star Orb), five speed skins, all ram designs, three Bubble skins, and Waldo. All listed catalog concepts are unlocked for testing; roguelike skin rewards and unlock ownership are a later feature. Other controls tune level difficulty, projectile sizes/speeds, wall growth, spawn rates/weights, pickup lifetimes, treasure, Picture and Waldo events, arena grid/claimed-area appearance, and named balance profiles. Picture Library can save procedural scenes or import images. Waldo Library separately saves Waldo puzzle recipes for Waldo events. Pickup test buttons include each current pickup kind. Completed wall networks show the area percentage they newly claim; broken growing walls use the selected break effect.
- Speed, Ram, and Treasure pickups despawn after 20, 10, and 10 seconds by default. Extra lives do not despawn by default. Every pickup type has a Developer lifetime setting; zero means no despawn. Pickups pulse between opaque and transparent over their final five seconds, with the pulse strength increasing toward despawn. When adding a pickup type, ask the user whether and when it should despawn if they have not specified a lifetime.

## Tuning

Edit `mechanics.ts` to adjust the provisional defaults for ball count and speed, level scaling, claim target, simultaneous wall limit, wall growth speed, power-up interval and rarity weights, treasure eligibility and event duration/reward count, Picture event chance, wall-break effect, arena appearance, ram blast radius/strength, and leaderboard size. The Developer tab stages these values per run and can save local profiles. These are playtest defaults, not final balance decisions.

## Ball skin concepts

The default in-game ball skin is **Polished Chrome**; switch among Polished Chrome, Brushed Steel, and Machined Gunmetal from Developer → Skin Catalog. The comparison sheet in [`design/metal-ball-skin-options.svg`](design/metal-ball-skin-options.svg) preserves all three concepts. The four ram alternatives and original orb are selectable in-game; [`design/ram-pickup-options.svg`](design/ram-pickup-options.svg) shows the comparison concepts.

## Scope

This is a first playable systems prototype, not a release-ready game. Art, audio, onboarding, accessibility, and polished collision behavior remain future work.
